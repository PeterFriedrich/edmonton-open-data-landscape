## 3. Technical Learnings
- **A redeploy is two steps:** `server` checks out the worktree, then the owner runs a `sudo` restart. The worktree HEAD proves only the first. Check `ActiveEnterTimestamp` against the time of the checkout. S19 got this wrong once.
- **New owner actions go in `TODO.md` → `### Waiting on the owner`**, in `server`'s format above. Don't keep them only in a handoff. Actions that `server-ops` tracks (e.g. service restarts) don't go there.
- **`make_brief.py` shows `###` headings inside Open work as bold subheads.** So any change to `TODO.md` changes `docs/BRIEF.md`, a synced file, and that PR has to wait for the owner's merge.
