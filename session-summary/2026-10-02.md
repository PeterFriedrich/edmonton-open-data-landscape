## 3. Technical Learnings
- **Discovery API carries nearly everything:** columns, timestamps, licence,
  `parent_fxf`, custom fields (`classification.domain_metadata`). It has **no
  row counts**; those exist only in `/api/views` `cachedContents` (not harvested).
- Offset paging at `limit=100` was stable: no duplicates in 21 pages.
- Custom-field values are messy: trailing spaces, synonyms, case. Normalisation
  maps are in `src/inventory.py` `CUSTOM`.
- **Licence signals:** a bare "licence" (business/pet licences) and "Terms of
  Use" (the City's own terms) in a description are **not** third-party
  signals. That was a false-positive bug caught by spot-check.
- Most licence fields say "See Terms of Use". The page behind it,
  `data.edmonton.ca/stories/s/City-of-Edmonton-Open-Data-Terms-of-Use/msh8-if28/`,
  is said to hold OGL – City of Edmonton, but **nobody has read it live yet**.
- **Personal info risk:** `/api/views` top values and min/max can hold names
  and addresses. Never publish them unfiltered.
- The private repo is cloned at `data/raw/private-snapshots/` (gitignored, a
  nested repo). The probe responses are in `data/raw/probe_2026-10-01/`.
- **Gotchas:**
  - A DECISIONS row change after `make_brief.py --write` makes
    `test_committed_brief_is_current` fail. Regenerate the brief last.
  - `cmd | tail -1 && git commit` commits even when the tests fail. Check the
    test output itself.
- **Cron caveat:** cron runs the script from the main clone's working tree. If
  that clone has a branch checked out that predates `scripts/weekly_snapshot.sh`,
  the run fails and files an issue. Keep the main clone on master or a recent
  branch.
- **Peer sessions:** `server` owns cron and `research/README.md`. It won't take
  owner approval relayed through this session; the owner must tell it directly.
